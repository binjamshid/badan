BADAN Design System

A privacy-respecting, local-first personal health app rendered at two altitudes — calm and casual by default, deep and inspectable for power users — bilingual (English/Arabic) with RTL as a first-order concern.

This is the human-readable mirror of docs/design.md — same tokens, rendered live. Source of truth for both: design/design-tokens.json.

Colors

Every UI token ships a light and dark value from day one. Status colors never moralize a reading: above-range and below-range share one amber, direction carried by arrow + text, never a second hue.

Surfaces & text
Status (semantic)

Typography

Numerals are tabular/monospaced everywhere a value lives, so numbers never jitter as they update. Every token maps to a Dynamic Type text style, so the ramp scales with the user's preferred size.

Spacing

A strict 4pt scale, plus two named exceptions: cardPadding and the 44px touchMin minimum tappable target.

Radius

Soft and generous throughout — no sharp corners anywhere in the system. Radius scales up with a surface's size and prominence.

Elevation & Depth

One elevation cue for the whole app: a soft 5%-opacity shadow plus a 1px border hairline. Tinted status shapes intentionally skip the border — their translucent fill already reads as bounded.

BadanCard

Soft shadow (black @ 5%, 8pt blur, 6pt y-offset) + 1px border hairline, applied via badanElevation().

Do's and Don'ts

Do

  • Pair every status color with an icon and a text label — never rely on hue alone.
  • Use the same card/chip/grid components at both altitudes; change density, not the language.
  • Treat RTL as a full mirror, with numeric/time-axis data staying LTR inside it.
  • Route every color through its light/dark token pair.
  • Keep every tappable target at or above 44px, even in dense grids.

Don't

  • Introduce a second severity color for out-of-band readings.
  • Ship a screen or string without an Arabic translation and a verified RTL pass.
  • Reach for error/critical red outside its reserved, near-never-used case.
  • Add a sharp (0px) corner anywhere in the system.
  • Let power-mode density shrink type below the scaled ramp or drop a target under 44px.
