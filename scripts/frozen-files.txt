# BADAN Android port — frozen files.

# Checked by: scripts/check_frozen_files.sh [baseline-ref]  (defaults to the tag
# `android-port-scaffold`, which does not exist until Batch 1 of the port lands — see that
# script's own header for the graceful no-op behaviour before then.)
#
# Every path below is a magnet file: a shared collision surface that Batch 1 of the Android
# parity port (docs/adr/ADR-0012-android-parity-port.md) rewrites into its final, registry-based
# shape before freezing it. After the `android-port-scaffold` tag is cut, no task may edit any of
# these directly — extending them goes through a per-file/per-area registry entry instead (see
# docs/android-port-conventions.md, sections 2-3). A task that genuinely must amend one becomes a
# solo magnet-amendment task at a barrier, and the tag is re-cut afterwards.
#
# This list is the BACKSTOP, not the primary control (see scripts/check_task_ownership.sh and
# docs/android-port-conventions.md section 2 for why).
#
# One path per line. No inline "# comment" trailing a path — `git diff --exit-code <ref> --
# <pathspecs>` takes these lines literally, so a trailing comment would be read as (and fail to
# match) part of the path. Comments live on their own line above the entry they explain.
#
# Paths marked "(Batch 1 — not yet created)" do not exist in this commit. They are listed in
# advance, at the path the plan specifies or the natural Kotlin-convention path for the object
# name the plan gives, so the location is reserved and reviewable now. Batch 1 must create them at
# exactly these paths — or, if it genuinely can't, correct this file in the same change that
# creates the file, before cutting the scaffold tag.
